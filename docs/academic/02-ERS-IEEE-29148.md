# 02. ERS (Especificación de Requisitos de Software) - IEEE 29148

## 1. Introducción

### 1.1 Propósito

Especificar los requisitos del sistema `spa-rrhh` para su construcción, validación y evolución controlada.

### 1.2 Alcance

Sistema web para gestión de vacantes, postulaciones y contactos, con backoffice administrativo seguro.

### 1.3 Definiciones

- ERS/SRS: Software Requirements Specification.
- CU: Caso de Uso.
- RNF: Requisito No Funcional.
- ABCM: Alta, Baja, Cambio, Modificación.

### 1.4 Referencias

- IEEE 29148.
- Documentación técnica del repositorio en `/docs`.

### 1.5 Estructura y convención documental

- `RF-*`, `RNF-*`, `RN-*`: catálogo de requisitos y reglas (`04-RF-RNF-RN.md`).
- `CU-*`: catálogo y fichas de casos de uso (`05-CASOS-DE-USO.md`, `16-FICHAS-CU-IEEE-COMPLETAS.md`).
- `API-*`: endpoints trazables en `src/app/api`.
- `TEST-*`: evidencias unitarias/E2E en `src/lib/__tests__` y `tests/e2e`.

### 1.6 Criterio de trazabilidad

Cada requisito debe mapearse al menos a:
1. un CU,
2. un punto de implementación (API/componente/servicio),
3. una evidencia de prueba.

## 2. Descripción general

### 2.1 Perspectiva del producto

Aplicación web full-stack sobre Next.js App Router, con APIs internas y persistencia PostgreSQL.

### 2.2 Funciones del producto

- Gestión pública de vacantes.
- Gestión admin de vacantes/postulaciones/contactos.
- Seguridad de acceso, anti-abuso y auditoría.

### 2.3 Características de usuarios

- Usuario público sin autenticación.
- Administrador con autenticación y permisos operativos totales.

### 2.4 Restricciones

- Runtime serverless target (Vercel).
- Integraciones externas (Resend, UploadThing, Turnstile, Upstash).
